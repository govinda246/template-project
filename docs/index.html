初心者向け概要

ゲーム開発用の安全なコンテナ環境

TypeScript・Vite・Phaserを使う開発環境です。通常の開発をしやすくしながら、 外部通信、Docker権限、資格情報、重要ファイルへのアクセスを分離しています。

ゲームを起動する 詳細セキュリティ資料を見る GitHubを見る

30秒で分かる構成

開発、DNS検査、外部通信を担当する3つのコンテナに分けています。

ローカルPC
VS Code・ブラウザー → egress-proxy
通信の確認と中継 → devcontainer
Node.js・Vite・Phaser
開発

devcontainer

ソース編集、npm、Viteを実行します。外部との直接接続経路はありません。

通信

egress-proxy

許可されたHTTPS先だけを中継し、ゲーム画面もローカルPCへ転送します。

名前解決

dns-filter

許可リストと一致するDNS名だけを上流へ転送し、Docker内部DNSへの迂回も遮断します。

分離

Bubblewrap

コマンドごとにプロセス空間を分離し、重要フォルダーを読み取り専用にします。

この環境がしていること

主な防御
  • 許可リスト外の外部通信を拒否
  • Docker socketを非公開。起動時capabilityはentrypoint後に全て除去
  • GitHub・クラウドの資格情報を渡さない
  • .gitや信頼スクリプトを読み取り専用にする
  • 端末・編集を手動承認で実行
残る注意点
  • 許可したnpm/GitHubの内容自体は安全とは保証されない
  • 書き込み可能なゲームファイルは破壊・改ざんされ得る
  • 資源消費やカーネル脆弱性を完全には防げない
  • Publicリポジトリへ秘密をコミットすると公開され得る

目的別の起動・再構築手順

ゲームを起動するだけなのか、Dockerなどの設定を変更したのかで操作が異なります。

初回・普段のゲーム起動
  1. Docker Desktopを起動
  2. VS Codeでリポジトリを開く
  3. 「Reopen in Container」を選ぶ
  4. コンテナ内ターミナルで下記を実行
npm ci
npm run dev

VS Codeの「ポート」ビューで egress-proxy:3000 の転送URLを開きます。 npm ci は初回または依存関係変更後だけで構いません。

コンテナ設定を変更した後

.devcontainer、Dockerfile、Compose、allowlist、secure-runなどを変更した場合は、 VS Codeの「Dev Containers: Rebuild Container」を実行します。 この操作はゲーム起動とは別で、コンテナの設計変更を反映する手順です。 

bash scripts/verify-security.sh

再構築後にコンテナ内でセキュリティ検証を実行します。DNSのCompose統合検証は Node.jsとDocker CLIがあるホスト側でnode scripts/verify-dns-security.mjsを 実行し、その後npm run devでゲームを確認します。

判断の目安: src やゲームコードだけを変更した場合は再構築不要です。 Docker・ネットワーク・VS Code設定・allowlist・セキュリティスクリプトを変更した場合は再構築が必要です。

安全性の位置づけ

追加対策なし 0 / 100

ホストで無制限に実行する基準状態。

現在の構成 71 / 100

通信・権限・資格情報を重点的に分離した設計比較値。

より強い構成 100 / 100

使い捨てVM、完全オフライン、署名検証、外部監視、復旧を含む基準。

点数の意味: 10項目の防御実装を比較する独自値であり、71%安全や絶対的な安全性を示すものではありません。 現在の通信・権限制御、資源上限、回帰テスト、依存関係監査などは71点の配点へ反映済みで、 対策追加のたびに自動加点されるものではありません。 詳細な採点根拠、できないこと、制限緩和時のリスクは 詳細セキュリティ資料へ分離しています。
